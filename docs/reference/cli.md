# Command-line interface

Run project commands through `uv run` from the repository root so the tracked
environment and git-sourced dependencies are selected.

## `lan-sbatch`

The installed entry point for `sbatch_scripts.gen_sbatch` has these commands:

```bash
uv run lan-sbatch init --help
uv run lan-sbatch generate --help
uv run lan-sbatch jaxtrain --help
uv run lan-sbatch torchtrain --help
uv run lan-sbatch recover --help
uv run lan-sbatch run --help
```

### `init`

Scaffold an experiment directory (see
[Define and run an experiment](../how-to/define-an-experiment.md)).

| Option | Required/default | Meaning |
| --- | --- | --- |
| `NAME` | required | Experiment name; letters, digits, `.`, `_`, `-` |
| `--dir PATH` | `experiments` | Parent directory |
| `--model TEXT` | `ddm` | ssm-simulators model written into both stage configs |
| `--quick` | false | Copy the `configs/quick_test` templates instead of `configs/examples` |
| `--network-type TEXT` | `lan` | `lan`, `cpn`, `opn`, or `gonogo` |
| `--trainer TEXT` | `jaxtrain` | `jaxtrain` or `torchtrain` |
| `--force` | false | Overwrite a non-empty directory |

Prints one JSON object with `experiment_dir`, `lineage_id`, and `experiments`.

### Options shared by the job commands

| Option | Meaning |
| --- | --- |
| `--experiment DIR` | Read config path, output path, model, lineage id, experiment names and tags from an experiment directory; explicit flags override |
| `--lineage-id TEXT` | Lineage id shared by every stage (MLflow tag `lineage_id`, rendered as `--lineage-id` in the job). Default: the experiment's; a real `generate` without one mints a fresh id and reports it |
| `--mlflow-tag KEY=VALUE` | Extra MLflow tag, repeatable; `schema_version`, `phase`, `lineage_id` are refused |

`--config-path` and `--output-path` are required unless `--experiment` supplies
them.

### `generate`

| Option | Required/default | Meaning |
| --- | --- | --- |
| `--config-path PATH` | required or from `--experiment` | ssm-simulators generation YAML |
| `--output-path PATH` | required or from `--experiment` | Data output root; generated scripts/logs use its `runs/` child |
| `--n-jobs-in-array INTEGER` | `1` or from `--experiment` | Slurm array size before optional lane splitting |
| `--n-files INTEGER` | unset | Files generated by each worker |
| `--cluster-config PATH` | unset | Shared cluster YAML; adjacent `.local.yaml` is merged automatically |
| `--use-all-lanes` | false | Split an array across configured CPU lanes and emit one result per lane |
| `--account`, `--partition` | config/fallback | Explicit scheduling overrides |
| `--num-gpus`, `--cores`, `--mem`, `--time` | config/fallback | Explicit resource overrides |
| `--script-only` | false | Render without submitting or creating MLflow state |
| `--log-level TEXT` | `WARNING` | `DEBUG`, `INFO`, `WARNING`, `ERROR`, or `CRITICAL` |

The rendered `generate` command also receives `--n-cpus` equal to the resolved
core request.

### `jaxtrain` and `torchtrain`

The trainer commands have the same interface and differ only in the LANfactory
console command embedded in the script.

| Option | Required/default | Meaning |
| --- | --- | --- |
| `--config-path PATH` | required or from `--experiment` | LANfactory training YAML |
| `--output-path PATH` | required or from `--experiment` | Network output root |
| `--training-data-folder PATH` | optional | Generated data consumed by the trainer. Omit with `--data-generation-experiment-id` to let LANfactory derive it from the generation runs (MLflow-first) |
| `--network-id INTEGER` | `0` or from `--experiment` | Network configuration index |
| `--data-generation-experiment-id TEXT` | unset | MLflow generation experiment linked as input lineage |
| `--cluster-config PATH` | unset | Shared cluster YAML plus automatic personal overlay |
| `--account`, `--partition` | config/fallback | Explicit scheduling overrides |
| `--num-gpus`, `--cores`, `--mem`, `--time` | config/fallback | Explicit resource overrides |
| `--dl-workers INTEGER` | `1` | LANfactory dataloader worker count |
| `--script-only` | false | Render without submitting or creating MLflow state |
| `--log-level TEXT` | `WARNING` | Logging threshold |

### `recover`

Submit parameter-recovery fits for an experiment's network: one Slurm array per
design × likelihood cell, each task one `lan-recover` fit tracked with
`hssm.track`. Runs under `uv run --group validate`.

| Option | Required/default | Meaning |
| --- | --- | --- |
| `--experiment DIR` | required | Experiment directory |
| `--onnx-path PATH` | `state.json`, else newest ONNX under the training output | Network under test |
| `--design TEXT` | `stages.recover.designs` | Repeatable |
| `--likelihood TEXT` | `stages.recover.likelihoods` (+ `analytical` when `add_reference_arm`) | Repeatable |
| `--n-datasets INTEGER` | `stages.recover.n_datasets` | Array size per cell |
| `--lineage-id`, `--mlflow-tag` | shared options | As above |
| `--cluster-config PATH` | unset | `job_defaults.recover` supplies resources |
| `--account`, `--partition`, `--cores`, `--mem`, `--time` | config/fallback | Explicit overrides (no GPUs) |
| `--script-only` | false | Render without submitting or touching MLflow |

### `run`

Run an experiment's stages on the current machine as subprocesses of the same
console scripts the Slurm jobs use. Slurm chaining is not implemented.

| Option | Required/default | Meaning |
| --- | --- | --- |
| `--experiment DIR` | required | Experiment directory |
| `--local` | required | The only mode; refused without it |
| `--stages TEXT` | all five | Comma-separated subset of `generate,train,validate,recover,summary`, run in that order |
| `--dry-run` | false | Log each stage's command; run nothing, write no state |
| `--continue-on-gate-failure` | false | Proceed past a failed validation gate |
| `--log-level TEXT` | `INFO` | Logging threshold |

Each stage records its outputs in `state.json`; a later invocation with a
subset of stages reads them (for example `--stages recover,summary` after a
finished training). `validate` and `recover` need the `validate` dependency
group. Prints one JSON object (see the JSON contracts).

## `lan-validate`, `lan-recover`, `lan-aggregate`

Console-script names for `validation/validate_network.py`,
`validation/recover_parameters.py` and `validation/aggregate_recovery.py`, so
generated jobs and drivers can call them by name. They need the `validate`
dependency group:

```bash
uv run --group validate lan-recover --help
```

`lan-recover` additionally accepts `--track/--no-track` (default: on when
`MLFLOW_TRACKING_URI` is set), `--mlflow-experiment-name`, `--mlflow-run-name`,
`--lineage-id`, `--mlflow-run-id-train` and repeatable `--mlflow-tag`; a tracked
fit lands in the inference experiment with `phase=infer`, the recovery
metrics, and the shard attached as `recovery_shard.json`.

## `lan-publish`

```bash
uv run lan-publish --help
```

| Option | Required/default | Meaning |
| --- | --- | --- |
| `--hf-repo TEXT` | required | Non-production Hugging Face target; there is deliberately no default |
| `--run-id TEXT` | selection A | Exact MLflow training run |
| `--model TEXT` | selection B | Model for newest-completed-run selection |
| `--network-type TEXT` | selection B | `lan`, `cpn`, `opn`, or `gonogo` |
| `--artifact-dir PATH` | run output path | Local folder holding the training artifacts |
| `--staging-dir PATH` | temporary directory | Persistent isolated upload assembly directory |
| `--skip-density` | false | Skip G4 for a shorter rehearsal; the result cannot publish |
| `--dry-run` | false | Validate and print the plan without HF/MLflow publication writes |
| `--overwrite-root` | false | Intentionally replace an existing canonical root artifact |
| `--log-level TEXT` | `INFO` | Logging threshold |

Pass `--run-id`, or pass both `--model` and `--network-type`. The source run's
recorded parameters remain authoritative after selection.

## Network validation

```bash
uv run python validation/validate_network.py --help
```

| Option | Required/default | Meaning |
| --- | --- | --- |
| `--onnx-path PATH` | required | Trusted ONNX artifact; sibling config may be unpickled |
| `--model-name TEXT` | required | ssm-simulators model name |
| `--network-type TEXT` | `lan` | `lan`, `cpn`, `opn`, or `gonogo` |
| `--report-path PATH` | next to ONNX | Detailed JSON report destination |
| `--skip-density` | false | Mark density skipped |
| `--skip-hssm` | false | Mark HSSM integration skipped |
| `--hellinger-ratio-max FLOAT` | `3.0` | Maximum density error relative to sampling floor |
| `--log-level TEXT` | `WARNING` | Logging threshold |

## Cluster discovery

```bash
uv run python scripts/discover_cluster.py --help
```

| Option | Default | Meaning |
| --- | --- | --- |
| `--ssh-host TEXT` | local shell | Run read-only Slurm queries through an SSH config host |
| `--output PATH` | `configs/cluster/oscar.local.yaml` | Personal overlay destination |
| `--print` | false | Print generated YAML instead of writing it |

## Visual inspection

```bash
export INSPECT_ONNX="/path/to/candidate.onnx"
export INSPECT_MODEL="ddm"
uv run --group inspect marimo edit validation/inspect_network.py
```

The inspector is a marimo application configured through environment variables,
not a stable machine interface.

## Documentation

```bash
./scripts/docs.sh build
./scripts/docs.sh serve
```

`build` always adds MkDocs strict mode. Both commands sync only the locked
`docs` group with Python 3.12 and do not install the project.
